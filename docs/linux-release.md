# Marten Commander v0.3.0 — Linux amd64

Этот архив содержит production-бинарник Marten Commander для Linux amd64. Фронтенд
встроен в executable; Vite dev server и исходники проекта для запуска не нужны.

## Системные зависимости

Для запуска в Ubuntu установите runtime-библиотеки GTK4 и WebKitGTK 6.0:

```sh
sudo apt update
sudo apt install libgtk-4-1 libwebkitgtk-6.0-4 libglib2.0-bin
```

Для локальной сборки дополнительно нужны `build-essential`, `pkg-config`,
`libgtk-4-dev` и `libwebkitgtk-6.0-dev`. Артефакт CI собирается на
`ubuntu-24.04`; успешная сборка без графической сессии не заменяет ручную проверку
запуска GUI. Ручную приёмку релиз-кандидата планируется провести на Ubuntu 26.04.

Если загрузчик сообщает об отсутствующей библиотеке, выведите динамические
зависимости командой:

```sh
ldd ./marten-commander
```

## Скачивание и запуск

1. Откройте вкладку **Actions** репозитория и успешный запуск workflow **Linux build**.
2. В разделе **Artifacts** скачайте `marten-commander-v0.3.0-linux-amd64`.
3. GitHub выдаёт артефакт во внешней ZIP-обёртке. Выполните из каталога загрузок:

```sh
unzip marten-commander-v0.3.0-linux-amd64.zip \
  -d marten-commander-v0.3.0-linux-amd64-actions
cd marten-commander-v0.3.0-linux-amd64-actions
sha256sum --check marten-commander-v0.3.0-linux-amd64.tar.gz.sha256
tar -xzf marten-commander-v0.3.0-linux-amd64.tar.gz
cd marten-commander-v0.3.0-linux-amd64
./marten-commander
```

Actions Artifact — временный результат CI, а не публичный GitHub Release. Для v0.3.0
workflow хранит его 21 день и не создаёт тег или Release.

## Ручная smoke-проверка

- [ ] Приложение запускается из распакованного каталога вне checkout репозитория.
- [ ] Обе панели открывают Home и показывают реальные файлы независимо друг от друга.
- [ ] Селектор томов, быстрый переход Home и сведения о свободном месте работают.
- [ ] Двойной щелчок, Enter, `..`, Backspace и ввод пути меняют каталог ожидаемой панели.
- [ ] Tab переключает панели из списка и возвращает фокус из командной строки.
- [ ] Ctrl/Shift создают множественное выделение, не смешивая его с текущей строкой.
- [ ] Обычный файл открывается через назначенное системное приложение.
- [ ] `cd ..`, абсолютный/относительный путь, quoted path и `cd ~/...` работают в командной строке.
- [ ] F4 открывает файл во внешнем редакторе; F5/F6/F7 выполняют копирование,
      перемещение/переименование и создание каталога.
- [ ] F8 требует подтверждение, переносит тестовые объекты в системную корзину и
      позволяет восстановить их средствами файлового менеджера ОС.
- [ ] SFTP-профиль подключается с ожидаемой проверкой host key; стартовый путь,
      Enter, двойной щелчок, `..` и Backspace работают в удалённой панели.
- [ ] F5 скачивает обычный SFTP-файл в локальную панель; совпадает SHA-256,
      конфликт предлагает безопасное решение, отмена не оставляет временный файл.
- [ ] F3 открывает локальный и удалённый обычный файл во встроенном Viewer.
- [ ] После штатного отключения SFTP панель возвращается в прежний локальный
      каталог, а Enter и Backspace продолжают локальную навигацию.
- [ ] Space показывает «Считается…» и размер локального каталога, не блокируя UI;
      в SFTP-панели удалённый каталог локально не обходится.
- [ ] Правила из `style.yaml` окрашивают только имена подходящих файлов в обеих
      панелях; курсор сохраняет цвет маски, явное одиночное/множественное выделение
      временно использует штатный цвет выделенного текста, снятие выделения
      восстанавливает маску. Каталоги и `..` сохраняют штатный вид.
- [ ] Внешняя команда запускается в системном терминале, а `cd` остаётся встроенной.
- [ ] Отказ в доступе показывает ошибку и сохраняет последний успешно открытый каталог.
- [ ] Интерфейс остаётся доступным после изменения размера окна.

Известные ограничения перечислены в `RELEASE_NOTES.md` внутри архива.
