# Архитектура MVP: шаги 1–3

Реализованы модели, LocalFileSystem для чтения и подключение реальных каталогов
к двум панелям React через application service и Wails 3.

## Границы пакетов

- `internal/core`: модели и контракты, только стандартная библиотека Go.
- `internal/localfs`: адаптер `os` для локальной файловой системы.
- `internal/app`: чтение снимка каталога, начальный путь и навигация по ссылкам.
- `internal/settings`: будущее хранение конфигурации и состояния в JSON.
- `internal/desktop`: Wails-адаптер, DTO и обратимые идентификаторы путей.

Пакет `settings` пока не создан. Новых библиотек нет; уже используемый
`ag-grid-community` объявлен прямой зависимостью frontend. Существующий
Go module path `github.com/rikkimongoose/marten-commander` сохранён.

## Контракт чтения

`core.FileSystem` имеет только три метода: `ReadDir`, `Lstat`, `Open`.
`core.LinkReader` отдельно предоставляет `Readlink`, а `core.PathResolver` —
`ResolvePath` для явного перехода по ссылкам. Запись, наблюдение и
информация о возможностях записи появятся вместе с соответствующими сценариями.
Отсутствие методов записи сейчас не означает, что физический диск read-only.

`localfs.LocalFileSystem` не хранит изменяемого состояния; его нулевое значение
готово к использованию и допускает параллельные вызовы. Каждый `Open` возвращает
свой поток. Другие реализации не обязаны разделять эти особенности адаптера.

Принимаются абсолютные пути в формате текущей ОС. Относительный или пустой путь
возвращает ошибку с причиной `fs.ErrInvalid`. Это исключает зависимость адресов
панелей от текущего рабочего каталога процесса. `Chdir` не используется.
Application service получает начальный каталог от точки входа: домашний каталог,
или рабочий каталог, если домашний путь определить не удалось. Перед чтением
`LocalFileSystem.ResolvePath` разрешает ссылки средствами ОС. Панель показывает
физический путь; переход к родителю вычисляется от этого пути. Нельзя автоматически удалять сегменты `..` после символической
ссылки: на Unix это может изменить адресуемый объект. Адаптер сохраняет префикс
пути при формировании адресов записей.

`FileEntry` содержит имя, путь, вид записи, размер, время изменения и `fs.FileMode`.
Размер и метаданные берутся у самой записи. Для каталогов, ссылок и специальных
файлов размер не следует показывать как размер обычного файла или содержимого
дерева. ACL, xattr, владелец и дополнительные метаданные пока не моделируются.

`ReadDir` читает каталог пакетами, без фильтрации скрытых файлов, без рекурсивного
обхода и без сортировки. Для пустого каталога возвращается пустой ненулевой slice
(`[]`, а не `nil`). Список включает метаданные каждой записи. Если каталог или запись
исчезает либо получение метаданных завершается ошибкой, возвращается ошибка без
частичного списка. UI оставляет предыдущий снимок и показывает ошибку; нельзя представлять неудачное чтение как пустой каталог.
Чтение не является атомарным снимком изменяющейся файловой системы.

Методы сохраняют причины ошибок для `errors.Is` и адреса для `errors.As` с
`*fs.PathError`. Контекст должен быть ненулевым. Отмена проверяется перед
системными вызовами, между записями каталога и при чтении потока. Она кооперативная:
произвольный заблокированный вызов ОС нельзя гарантированно прервать контекстом.
Адаптер не создаёт goroutine ради имитации отмены.

## Символические ссылки и специальные файлы

- `Lstat` и записи `ReadDir` описывают саму ссылку, включая битые и циклические.
- `Readlink` возвращает точное содержимое ссылки, включая относительный адрес;
  он не разрешает её цель и не требует существования цели.
- `ReadDir` явно следует ссылке на каталог, переданной как открываемый путь.
- `Open` явно следует ссылке на обычный файл и возвращает поток только для чтения.
- Каталоги и специальные файлы нельзя открыть через `Open`: `fs.ErrInvalid`.
  В частности, известный FIFO отвергается до открытия, чтобы не ждать писателя.

Тип проверяется до открытия и по открытому дескриптору. Проверка пути и открытие
не образуют транзакцию: другой процесс способен заменить запись между ними.
Это не файловая песочница и не защита от враждебной одновременной подмены путей.
Ограничения на блокирующие системные вызовы действуют и при такой подмене.

Поток необходимо закрыть, в том числе после отмены. Контекст `Open` действует
также на последующие `Read`; адаптер не закрывает поток автоматически по отмене.
Дескриптор каталога принадлежит адаптеру и закрывается на всех путях возврата.

## Имена файлов на границе Go/TypeScript

В Go сохраняются исходные байты имён, включая пробелы, Unicode, переводы строк,
специальные символы и допустимые в Linux последовательности вне UTF-8. Ограничения
конкретной ОС сохраняются; например, Windows запрещает часть таких имён.

`FileEntry` — внутренняя модель, не DTO Wails. Нельзя передавать её путь через JSON
и использовать полученную строку как адрес для файловых операций: невалидный
UTF-8 может быть заменён, а разные исходные имена — стать неразличимыми.
Wails-адаптер кодирует исходные байты пути через base64url без padding. Этот ID
используется для переходов, обновления и getRowId таблицы. Отображаемые строки
отдельно экранируют управляющие символы, обратные слеши и невалидные UTF-8 байты.
Отображаемая строка никогда не используется как адрес перехода по записи.

Поле ручного перехода принимает абсолютный путь в обычном формате ОС, без
декодирования escape-последовательностей. Путь с невалидным UTF-8 можно открыть
через запись родительского каталога, но нельзя полностью набрать в Unicode-поле.
Идентификаторы не являются разрешениями доступа: приложение работает с правами
текущего пользователя, без файловой песочницы.

Размер файла передаётся десятичной строкой, чтобы сохранить int64 вне точного
диапазона JavaScript Number. Сравнение размеров использует BigInt. Время передаётся
в UTC с фиксированной точностью до наносекунд для сортировки; отображается
в локальном часовом поясе webview.

## Источник истины для порядка строк

Единственный источник порядка строк — **AG Grid на frontend**. Адаптер Go возвращает
несортированные записи; Go не поддерживает второй порядок строк и не пересчитывает
его при клике по заголовку. Модель сортировки управляется в одном frontend-модуле
панели через возможности AG Grid. React не хранит дополнительную сортированную
копию массива. Сохранение sort model в state.json будет снимком предпочтений,
а не ещё одним активным источником истины.

Компаратор учитывает инверсию, которую AG Grid выполняет для descending, и
компенсирует её для строки `..` и группы каталогов. Каталоги и доступные ссылки на них
остаются впереди при любом направлении. Поддерживаются имя, расширение, размер
и время; при равных значениях сравниваются имя и ID. Multi-sort отключён.
Для имён используется русская locale с естественным порядком чисел.
Экранированные необычные имена сортируются по отображаемой строке.

Флаг скрытого файла вычисляет LocalFileSystem: имя с точкой, а на Windows также
атрибут HIDDEN. Переключатель каждой панели фильтрует её снимок без нового чтения
Go. Фильтрация не меняет порядок исходного массива. Скрытая из таблицы строка
теряет выделение; это исключает невидимое выделение для будущих команд.

## Состояние панелей и асинхронные запросы

Каждый FilePanel владеет своим подтверждённым каталогом, снимком записей,
переключателем скрытых файлов и AG Grid instance. Grid хранит выделение и sort
model. Текущая запись сохраняется по ID, а viewport — по верхней видимой строке.
При удалении текущей записи выбирается ближайшая по прежнему индексу.
Восстановление фокуса не должно перехватывать ввод из соседней панели или поля пути.
Прокрутка восстанавливается с точностью до строки, не до отдельного пикселя.

Go-сервис не хранит копию состояния панелей. Это упрощение первоначального плана:
на данном этапе Go достаточно возвращать независимый снимок по запросу.
Состояние каталогов не требуется синхронизировать между двумя владельцами.

DirectoryLoader каждой панели имеет один активный и один заменяемый ожидающий
запрос. Новое намерение увеличивает номер запроса и запрашивает отмену предыдущего
Wails promise. Устаревшие ответы и ошибки отбрасываются независимо от успешности
отмены. Сравнивается номер, а не путь, что защищает и переход A → B → A.
При размонтировании обработчик отменяется; React StrictMode не создаёт вечных
подписок. Ограничение кооперативной отмены блокирующих вызовов ОС сохраняется.

Ошибка не меняет подтверждённый путь, не заменяет список пустым и сопровождается
сообщением о том, что остался предыдущий снимок. Ручной путь остаётся доступен,
даже если первоначальная загрузка завершилась ошибкой.

Двойной щелчок и Enter открывают каталог или обычный файл, Backspace переходит к
родителю, Ctrl/Cmd+R в таблице обновляет текущий снимок. Переход по ссылке на
каталог разрешает её физический путь. Битая,
циклическая или недоступная ссылка остаётся видимой; причина доступна в подсказке.

`main.go` регистрирует новый Wails service; демонстрационная goroutine времени
удалена. Bindings создаёт `wails3 generate bindings -ts -i`; ручных правок в них нет.

## Навигация панелей (Issue #2)

`panelRows.ts` добавляет строку `..` только при `location != parentLocation`.
Это UI-строка с отдельным признаком `parent`, а не файл в снимке Go. Она всегда
первая при любой сортировке, не входит в счётчик файлов, не выделяется и не
попадает в `selectedLocations`. Когда курсор на ней, `focusedLocation` равен
`null`; её открытие выполняет навигационную команду с ID строки в параметрах.
AG Grid остаётся единственным владельцем порядка строк и явного выделения.
Явно выделенные Ctrl/Cmd строки и Shift-диапазоны показываются красным; текущая
строка обозначается отдельной синей рамкой и может не входить в выделение.
Клик с модификатором меняет только явное выделение и не перемещает текущую строку.
Исключение — Ctrl/Cmd-клик по неактивной панели: он активирует панель, делает
нажатую строку текущей и гарантированно добавляет её в явное выделение.

`panel.openEntry`, `panel.goToParent` и `panel.switch` зарегистрированы в
существующем CommandDispatcher. Enter и двойной щелчок используют общий метод
`open()`: каталог направляется в `panel.openEntry`, обычный файл — в `file.open`.
Метод панели проверяет захваченный адрес исходного каталога и доступность записи
перед навигацией. В корне переход вверх — no-op.
Выбор Home и томов по-прежнему использует `panel.goToLocation` и VolumeService.

При успешной смене каталога явное выделение очищается. Возвращение к родителю
восстанавливает курсор по адресу покинутого каталога в уже отсортированной
таблице; если запись исчезла или скрыта, выбирается первая доступная строка.
Обычное обновление сохраняет курсор, выделение и прокрутку по прежним правилам.
Переход по символической ссылке по-прежнему использует физический путь: возврат
идёт к его физическому родителю, а не является историей переходов по ссылкам.

Tab и Shift+Tab из списка переключают активную панель и вызывают `focusList()`:
курсор возвращается на её прежнюю строку, а в пустом списке фокусируется контейнер.
Начальная загрузка фокусирует список активной панели, только если пользователь
ещё не перевёл фокус в другой элемент. Поздний ответ не перехватывает ввод из
другой панели или поля пути. Активность отмечается прежней цветной рамкой.

Обработчик capture внутри списка забирает только команды навигации, обновления
и выделения всех файлов. Он игнорирует поля ввода, contenteditable и IME.
Стрелки, Space и вычисление Ctrl/Shift-выделения остаются у AG Grid; переход стрелкой выше
первой строки не уводит курсор в заголовок. Ctrl/Shift-клики сохраняют штатное
множественное выделение. После модификаторного клика технический фокус AG Grid
возвращается на текущую строку, не меняя рассчитанный набор. В остальном фокус
AG Grid остаётся технически на ячейке, но её рамка
скрыта, а отдельный класс `cursor-row` подсвечивает всю текущую строку. Это делает
клавиатурный курсор видимым на уровне строки и не смешивает его с `ag-row-selected`:
стрелки двигают курсор, не меняя явно выбранные Ctrl/Shift строки. Tab в поле пути и элементах панели вне списка сохраняет
обычное поведение браузера. Основание: [клавиатура AG Grid](https://www.ag-grid.com/react-data-grid/keyboard-navigation/)
и [множественное выделение](https://www.ag-grid.com/react-data-grid/row-selection-multi-row/).

## Открытие файлов (Issue #3)

`file.open` всегда получает `params.location` конкретной строки. Для Enter это
строка курсора, для двойного щелчка — строка события. Команда намеренно не применяет
`effectiveSelection()`: красное множественное выделение может содержать другие
файлы и передаётся только как неизменяемый контекст. Один frontend-обработчик
зарегистрирован через `registerFileCommands()` и использует прежний
`createCommandBackend()`/`CommandService.ExecuteCommand`.
Перед первым обычным кликом потенциального double-click панель сохраняет явное
выделение и восстанавливает его в `onRowDoubleClicked`; нажатая строка остаётся
текущей, но открытие само по себе не добавляет её в красный набор.

Wails-адаптер строго принимает один base64url-адрес, декодирует его в абсолютный
native-путь и вызывает `app.FileService`. Application service повторно выполняет
`Lstat` через существующий `LocalFileSystem` и разрешает только `KindFile`.
Каталоги остаются навигацией; символические ссылки и специальные объекты в этом
этапе внешним приложениям не передаются. Проверка и запуск не являются атомарной
границей безопасности: файл может быть заменён между системными вызовами.

`localfs.SystemFileLauncher` использует на Linux `exec.Command("xdg-open", path)`:
shell не создаётся, абсолютный путь является одним отдельным аргументом. Быстрый
отказ обработчика ожидается до 300 мс; более долгий процесс продолжает ожидаться
в goroutine и не удерживает Wails-команду. Windows вызывает `ShellExecuteW` с
verb `open`, поэтому использует системные ассоциации без командной строки.
Запуск не ждёт всё время работы открытого приложения. macOS использует аналогичный
прямой вызов `open` для сохранения собираемости поддерживаемой конфигурации.

Ошибки отсутствующего файла, недопустимого вида и системного обработчика возвращаются
как `CommandError(open_failed)` и отображаются общим Alert. Панель не меняет каталог,
курсор или выделение при запуске команды, поэтому ошибка не требует восстановления
снимка. Встроенный viewer/editor, меню и «Открыть с помощью» не добавлены.

## UI-команды (Issue #7)

`frontend/src/commands.ts` содержит небольшой реестр `CommandDispatcher`.
Каждый зарегистрированный `CommandId` имеет `available(context)`, опциональный
`prepare(context)` и `execute(request)`. Все источники запуска вызывают
`dispatch(id, params?)`. В Issue #7 добавлена `panel.selectAll`: кнопка
«Выделить всё» и Ctrl/Cmd+A в ячейке таблицы выделяют видимые записи активной
панели. В поле пути сочетание сохраняет обычное поведение текстового ввода.
Команда выполняется синхронно в React/AG Grid и не вызывает Go.

В Issue #1 добавлена `panel.goToLocation`. Параметры выбора копируются до
`prepare(context, params)` наравне с контекстом; целевая панель определяется
зафиксированным `activePanel`. Команда вызывает существующий загрузчик панели,
а не создаёт отдельную backend-операцию навигации.

Панели продолжают владеть своим состоянием. `FilePanelHandle.getContext()`
предоставляет только адрес каталога, явно выделенные адреса и отдельный адрес
текущего элемента. Диспетчер один раз копирует обе панели и `activePanel`,
замораживает объекты и массивы **до проверки доступности и открытия диалога**.
Пустое явное выделение остаётся пустым в снимке. `effectiveSelection()` во
frontend и одноимённый метод Go-модели задают единое правило для будущих групповых команд:
непустой `selectedLocations` используется
целиком, иначе операндом становится `focusedLocation`, а при отсутствии курсора
операндов нет. Источник — панель `activePanel`, получатель — противоположная.
Смена панели или выделения не меняет контекст начатого вызова.
Ссылки на React/AG Grid в снимок не попадают.

Контракт запроса: `{ id, type, context, params }`. `id` уникален для вызова,
`type` обозначает зарегистрированную команду. `context` содержит `activePanel`,
`left`, `right`; каждая панель содержит `directoryLocation`, `selectedLocations`,
`focusedLocation`. Это адаптация примера Issue к существующему контракту путей:
значения — **абсолютные native-пути в base64url**, как `Directory.location` и
`Entry.id`, а не отображаемые или потенциально повреждённые JSON-строки путей.
`null` означает отсутствие открытого каталога/текущей записи; выделение — всегда
массив, включая `[]`. Кодирование сохраняет невалидные UTF-8 имена Linux.

`prepare()` возвращает JSON-объект параметров либо `CANCEL_COMMAND`. При отмене
`execute` и Go не вызываются. После подтверждения параметры копируются и
замораживаются, затем обработчик получает запрос с исходным контекстом.
Неизвестная или недоступная команда не запускает диалог/обработчик. Ошибки
диспетчера имеют код `CommandError`; обычные исключения и rejected promises
преобразуются в `handler_failed` с исходной причиной. App показывает сообщение
через Alert. Универсального диалога, очереди и менеджера операций нет.

`commandBackend.ts` — единственный адаптер backend-команд: он вызывает
сгенерированный `CommandService.ExecuteCommand`, сохраняя `id/type/context/params`.
Wails загружается только при backend-вызове; в тестах подставляется mock binding.
Go проверяет envelope, панель, обратимость адресов, абсолютность native-путей,
отсутствие NUL и объектный формат `params`. Ошибки с кодом и сообщением доходят
через `RuntimeError.cause` до TypeScript. Поддерживаемый backend-тип `file.open`
вызывает application service; неизвестные типы и UI-команды по-прежнему получают
`unknown_command`. Успешного фиктивного результата нет.

Для новой UI-команды нужно расширить `CommandId` и зарегистрировать определение
рядом с существующим в App; кнопка/меню/shortcut вызывают тот же `dispatch`.
Для реальной backend-команды её `execute` использует `createCommandBackend()`.
В Go используется конкретная ветка по типу: строгое декодирование собственного
типа параметров с отказом от неизвестных полей, проверка значений и вызов
application service. Сервис операции обязан заново проверить адреса, доступ и
допустимость действия; текущая синтаксическая проверка контекста не подтверждает
существование файлов или права доступа. Обработчик не должен читать живое
состояние панелей после `prepare` и не должен зависеть от React/Wails UI.

## Локальные тома и Home (Issue #1)

`internal/volumes.Service` — независимый от UI read-only сервис с методами
`ListVolumes`, `GetVolumeInfo(path)` и `GetHomeDirectory`. Небольшая граница
`backend` отделяет перечисление, поиск и счётчики ОС; в тестах подставляется
источник данных. `internal/desktop.VolumeService` адаптирует результаты к Wails:
адреса используют прежнее base64url-кодирование native-путей, отображаемые строки
экранируются, uint64-счётчики передаются десятичными строками. Bindings генерируются.
Новых зависимостей или механизма монтирования нет; используется уже имеющийся
`golang.org/x/sys`.

На Linux читается `/proc/self/mountinfo` текущего mount namespace, включая
экранированные имена и optional fields. `/` всегда виден. Псевдофайловые системы
исключаются по типу; известные container overlay/bind mounts, snap-образы,
AppImage и разрешающие self-bind mounts — по сочетанию типа, источника, корня
mount и параметров. Нет запрета по одному префиксу `/var`, `/run`, `/mnt` и т. п.
Обычные разделы, пользовательские bind mounts, NFS/CIFS и доступные через локальное
монтирование FUSE-файловые системы остаются. Перед включением в селектор тип точки
проверяется через `O_PATH | O_DIRECTORY`: файловые bind mounts и исчезнувшие пути
исключаются без чтения содержимого или ёмкости устройства. Ошибка доступа не
скрывает том; пункт остаётся с предупреждением. Классификация служебных mounts
консервативная и не является универсальным распознавателем всех контейнерных
runtime. Фильтр списка не применяется к поиску содержащей файловой системы:
например, переход вручную в `/proc` не покажет ошибочно объём родительского `/`.

Для поиска сначала разрешаются ссылки и проверяется существование пути.
`statx(STATX_MNT_ID)` определяет фактический mount, включая bind/overmount;
на старых ядрах используется самое длинное совпадение с границей компонента пути.
Исчезнувший mount ID не подменяется родительским. `statfs` даёт счётчики:
`total = blocks × frsize`, `free = bfree × frsize`,
`available = bavail × frsize`, `used = total − free`.
Если `frsize` отсутствует, применяется `bsize`; переполнение и противоречивые
значения отвергаются. Отрицательный доступный остаток означает ноль доступного.

На Windows используются `GetLogicalDrives`, `GetDriveTypeW`,
`GetVolumeInformationW`, `GetVolumePathNameW` и `GetDiskFreeSpaceExW`.
Показываются диски с буквами, включая съёмные и mapped network drives; ошибка
метки одного устройства не скрывает остальные. Поиск учитывает вложенные точки
монтирования, а не просто букву пути. Счётчики относятся к доступной текущему
пользователю ёмкости/квоте: `used = total − available`.
Запросы метаданных съёмных носителей подавляют диалог «вставьте диск» через
временный режим текущего OS thread. Логика перечисления вынесена за `driveAPI`
для тестов на любой платформе. На прочих ОС Home работает, но тома возвращают
явное сообщение о неподдерживаемой платформе.

Список содержит метаданные, без обязательного чтения объёма каждого устройства.
Так Linux-селектор не ожидает `statfs` для всех потенциально зависших сетевых
mounts. Актуальная ёмкость запрашивается через `GetVolumeInfo` только для открытого
расположения. На Windows получение меток также может ждать ответа устройства.
Системный вызов к неисправной сети/носителю нельзя гарантированно прервать
контекстом; фоновые goroutine с искусственными таймаутами не создаются.

`VolumeBar` каждой панели самостоятельно обновляет список при открытии MUI Menu,
а информацию о текущем томе — при смене подтверждённого каталога и повторном
открытии селектора. Новый снимок того же каталога после ручного обновления также
обновляет ёмкость. Home всегда отдельный первый пункт, затем Divider и настоящие
тома. Путь Home получает `os.UserHomeDir()`, и он никогда не добавляется как mount.
Неудача перечисления томов не отключает успешно полученный Home, и наоборот.
Оба результата публикуются независимо: Home доступен, даже если перечисление
устройств ещё не завершилось. Закрытие меню и размонтирование компонента отменяют
его Wails-запросы; смена каталога отменяет прежний запрос ёмкости. Защита от поздних
ответов работает и для источника, который не поддерживает отмену.
После перехода Home индикатор определяется по реальному открытому каталогу.

Выбранный быстрый переход Home хранится отдельно от сведений о томе, локально
в каждой панели. Выбор фиксируется только вместе с последним успешным ответом
`DirectoryLoader`; ошибка или устаревший ответ не меняют ни список, ни выбор.
Подпись остаётся `Home` при обновлении и переходах внутри домашнего каталога,
даже если он находится на System или содержит другую точку монтирования.
При выходе за его пределы или явном выборе тома подпись снова определяется томом.
Обычный вход в домашний каталог сам по себе не включает быстрый переход Home.
При первоначальной загрузке backend сообщает `initialHome`, если стартовый путь
получен из `os.UserHomeDir()`: обе панели сразу выбирают Home. Резервный запуск
в рабочем каталоге при ошибке определения Home этот признак не устанавливает.
Для проверки принадлежности Go передаёт `ancestorLocations` — непрозрачные адреса
родителей разрешённого пути. React сравнивает адреса, не разбирая пути Windows,
невалидный UTF-8 или отображаемый текст. Символическая ссылка за пределы Home
считается выходом из него. Свободное место всегда относится к фактическому
открытому каталогу, независимо от подписи селектора.

При `fs.ErrPermission` адаптер сообщает «Нет прав на чтение каталога …».
Панель сохраняет последний успешный снимок и остаётся доступной для дальнейших
переходов; повышение привилегий и обход прав не выполняются.

Пользователь видит доступное ему свободное место и физически занятую долю Linux
(на Windows — занятую долю квоты). Разницу с резервом ОС поясняет tooltip.
Единицы — КиБ/МиБ/ГиБ и далее, вычисления используют BigInt. Нулевой, неизвестный
или некорректный объём даёт нейтральную серую полоску без чисел; ошибка получения
информации отображается текстом. Поздние ответы не заменяют данные нового пути.

Выбор вызывает `panel.goToLocation` через общий dispatcher. Для тома передаётся
его ID; `createPanelReader` проверяет, что адрес всё ещё соответствует выбранному
тому, и затем вызывает прежний `ReadDirectory`. Home использует обычный переход.
Проверка и чтение — один запрос существующего `DirectoryLoader`, поэтому смена
тома, ручной переход, обновление и размонтирование компонента используют прежнюю
защиту от устаревших результатов и ошибок. Ошибка оставляет последний успешно
прочитанный каталог. Проверка ID не атомарна с чтением: отключение/замена устройства
между системными вызовами остаётся обычной гонкой файловой системы. Windows ID
обозначает mount root, а не серийный номер физического носителя.

Основания платформенного контракта:
[Linux mountinfo](https://www.kernel.org/doc/Documentation/filesystems/proc.txt),
[GetLogicalDrives](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getlogicaldrives),
[GetVolumePathNameW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getvolumepathnamew),
[GetDiskFreeSpaceExW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdiskfreespaceexw).

## Требования для следующих шагов

Эти пункты зафиксированы как ограничения будущей реализации, а не как готовые
возможности:

- DirectoryWatcher сначала получает минимальное поведение для двух панелей;
  дополнительные механизмы добавляются при подтверждённой необходимости.
- Если слияния существующих каталогов ещё нет, конфликт должен явно сообщать
  об этом ограничении. Молчаливый пропуск недопустим.
- Рекурсивное удаление непустого каталога обязательно требует подтверждения.
- Копирование и удаление не должны неявно обходить цели символических ссылок.
- Безопасная замена файла требует временного файла рядом с назначением,
  проверки ошибок записи/закрытия и платформенного механизма установки.
  Нельзя уничтожать прежнее назначение до успешного завершения записи.
- Защита от копирования в себя, случайной перезаписи и подмены назначения
  проектируется вместе с изменяющими операциями. Сейчас методов записи нет.

## Проверка

Из корня проекта:

```sh
go test ./internal/...
go test -race -cover ./internal/...
go vet ./internal/...
cd frontend
npm test
npm run build
```

Go-тесты внутренних пакетов не требуют Wails, GUI или frontend-сборки.
Frontend-тесты используют встроенный node:test, без новых библиотек. Если стандартный Go build cache недоступен для записи,
можно задать `GOCACHE` в доступном временном каталоге.

Модульные тесты классифицируют виды записей. Интеграционные тесты используют
`t.TempDir()` и проверяют метаданные, скрытые и необычные имена, несколько пакетов
чтения, символьные ссылки, ошибки, отмену и конкурентное чтение. Linux-тесты
дополнительно проверяют невалидный UTF-8, FIFO, права доступа и пути `ссылка/..`.
Тест прав доступа пропускается при запуске от root. На Windows тест ссылок может
быть пропущен при отсутствии необходимых разрешений. Проверки иных платформ
сборкой не заменяют запуск тестов на соответствующей ОС.

Тесты application layer проверяют начальный путь, независимые запросы, сохранение
ошибок и отмены, переходы к родителю и по ссылке. Тесты адаптера проверяют DTO,
JSON round trip невалидного UTF-8, точность размеров/времени и ошибки запросов.
Frontend-тесты проверяют все сортировки в обоих направлениях, скрытые файлы,
восстановление курсора, устаревшие ответы/ошибки, отмену реального Wails
CancellablePromise и размонтирование. Тесты команд проверяют source/target,
неизменяемость обеих панелей во время диалога и асинхронного обработчика, отмену,
несколько источников dispatch, доступность, ошибки и mock Wails binding.
Go-тесты контракта проверяют envelope, адреса, параметры, неподдерживаемые типы
и сохранение кодов ошибок/необычных путей при JSON round trip.
Полную проверку нативного фокуса и мыши
нужно выполнять в запущенном Wails-приложении; сборка её не заменяет.
