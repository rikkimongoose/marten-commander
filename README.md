# Marten Commander

Двухпанельный файловый менеджер на Go, Wails 3, React, MUI и AG Grid.
Текущая версия MVP — 0.1.0: чтение локальных каталогов, независимые файловые
панели, навигация и открытие файлов системным приложением.

## Возможности текущего этапа

- Обе панели начинают с домашнего каталога и независимо переходят по файловой системе.
- Над каждой панелью — выбор локального тома и отдельный быстрый переход Home,
  свободное место и индикатор заполненности. Linux использует реальные mounts,
  Windows — диски с буквами; список обновляется при открытии селектора.
  Home доступен, не дожидаясь медленного устройства. Ручное обновление каталога
  также обновляет сведения о свободном месте.
- Переход по абсолютному пути, двойному щелчку или Enter; строка `..` и Backspace —
  к родителю. При возврате курсор устанавливается на покинутый каталог, если он виден.
- Enter и двойной щелчок по обычному файлу открывают его в назначенном приложении ОС.
- F4 или кнопка «Правка» открывают обычный файл под курсором во внешнем графическом
  текстовом редакторе. Явное множественное выделение при этом не меняет выбранный файл.
- Tab/Shift+Tab из файлового списка переключают панели и переводят фокус в список;
  стрелки перемещают курсор независимо от явного выделения.
- Имена, расширения, типы, размеры и время изменения; сортировка кликом по заголовку.
- Каталоги и доступные ссылки на каталоги всегда впереди, включая обратную сортировку.
- Независимый переключатель скрытых файлов и красное множественное выделение
  Ctrl/Cmd/Shift произвольных строк, отдельное от синей строки текущего элемента.
- Ручное обновление кнопкой или Ctrl/Cmd+R в таблице, сохранение доступных выбранных
  записей, текущего элемента и верхней строки при обновлении того же каталога.
- «Выделить всё» кнопкой или Ctrl/Cmd+A в таблице через общий CommandDispatcher;
  неизменяемый контекст обеих панелей и минимальный Wails-контракт команд.
- F5 копирует выбранные файлы и деревья в каталог второй панели через фоновые
  операции. Доступны прогресс, отмена, Replace/Skip/Keep both, Merge каталогов
  и apply-to-all для совместимых конфликтов. Символические ссылки копируются
  как ссылки и не обходятся рекурсивно.
- F6 перемещает или переименовывает выбранные объекты. В пределах одного Linux
  filesystem используется условный `renameat2`; при `EXDEV` выполняется
  copy→verify→conditional delete. Skip и Cancel сохраняют источник, а Merge
  удаляет только действительно опустевшие исходные каталоги.
- Защита от устаревших ответов; ошибка оставляет последний успешный снимок.

Наблюдение за каталогами, удаление, встроенные редактор
и просмотрщик, «Открыть с помощью» и экран настроек ещё не реализованы. Изменения файловой
системы появляются после ручного обновления.

## Внешний редактор F4

По умолчанию используется режим `auto`. В Linux Marten Commander ищет первый доступный
GUI-редактор в порядке GNOME Text Editor, Gedit, Kate, Visual Studio Code и VSCodium.
Консольные редакторы без терминального эмулятора автоматически не запускаются.

До появления экрана настроек редактор задаётся переменными окружения перед запуском
Marten Commander. Аргументы — JSON-массив отдельных аргументов процесса. Токен `{file}`
можно указать отдельным элементом; если его нет, путь файла добавляется последним:

```sh
MARTEN_COMMANDER_EDITOR_MODE=custom \
MARTEN_COMMANDER_EDITOR_EXECUTABLE=/usr/bin/code \
MARTEN_COMMANDER_EDITOR_ARGUMENTS='["--reuse-window", "{file}"]' \
./bin/marten-commander
```

Изменение применяется при следующем запуске приложения. Команда запускается напрямую,
без shell: подстановки shell в пути, имени программы и аргументах не выполняются.

## Разработка и сборка

CI использует Go 1.27, Wails CLI 3.0.0, Node.js 24 и npm.
Версии frontend-зависимостей закреплены в `frontend/package-lock.json`.
Linux-сборке нужны C-компилятор, pkg-config, GTK4 и WebKitGTK 6.0 с development-файлами.
Для запуска GUI нужна графическая сессия.

```sh
cd frontend
npm ci
cd ..
wails3 dev
```

Стандартная сборка через существующий Taskfile:

```sh
wails3 build GOOS=linux GOARCH=amd64
```

Результат Linux-сборки — `bin/marten-commander`. Для явной проверки без задач,
обновляющих зависимости и иконки, можно использовать:

```sh
wails3 generate bindings -ts -i
cd frontend
npm run build
cd ..
go build -mod=readonly -tags production -buildvcs=false -o bin/marten-commander .
```

Bindings генерируются автоматически; вручную их редактировать не нужно.

## Тесты

```sh
go test -race -cover ./internal/...
go vet ./internal/...
cd frontend
npm test
npm run build
```

Go-тесты внутренних пакетов работают независимо от Wails и GUI. Frontend-тесты
используют встроенный Node.js test runner. Проверки в браузере не заменяют
проверку клавиатуры и фокуса в нативном webview.

Дополнительный браузерный тест использует настоящий App/AG Grid и подставные
ответы Wails. Нужны отдельно установленный `playwright-core` и Chrome; зависимости
приложения для него не изменяются. Из `frontend`:

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright-core/index.mjs \
CHROME_PATH=/absolute/path/to/chrome node tests/browser/navigation.mjs
```

Тест проверяет переходы, открытие файлов через Enter/двойной щелчок, ошибку
системного обработчика, Tab, стрелки, красное Ctrl/Shift-выделение, его независимость
от курсора, сброс выделения при переходе,
возврат курсора, пустой корень, отказ в доступе и отсутствие перехвата фокуса
неактивной панелью при позднем ответе.

## Ограничения

Переход по ссылке открывает её физический путь. Необычные имена отображаются
с экранированием; переходы по записям используют отдельные обратимые идентификаторы.
В поле пути вводится обычный абсолютный путь ОС, без escape-последовательностей.
Невалидный UTF-8 нельзя набрать в текстовом поле, но такие каталоги доступны
через родительскую панель на Linux. При скрытии строки её выделение снимается.
Системное открытие в этом этапе разрешено только для обычных файлов; ссылки и
специальные объекты не передаются внешним приложениям. Linux использует `xdg-open`,
Windows — `ShellExecute`.
Отмена не может гарантированно прервать заблокированный системный вызов.

Безопасная публикация результатов копирования сейчас реализована для Linux:
новые файлы публикуются через `renameat2(RENAME_NOREPLACE)`, а подтверждённая
замена проверяет fingerprint назначения и использует атомарный exchange. Запись
идёт во временный файл того же каталога; незавершённый файл удаляется при ошибке
или отмене. Уже опубликованные элементы пакетной операции не откатываются и
отражаются как частичный результат. На платформах без эквивалентных гарантий
копирование явно завершается ошибкой, не переходя к небезопасной замене.

Перемещение между файловыми системами не транзакционно: успешно опубликованная
копия остаётся при последующей ошибке удаления, операция получает частичный
результат, а исходный объект сохраняется. Перед удалением проверяется fingerprint,
и изменившийся источник не удаляется. Гарантии не распространяются на сбой
питания между отдельными системными вызовами. Безопасные примитивы F6 пока
реализованы только для Linux; другие платформы явно возвращают unsupported.

Подробные решения, контракты и ограничения: [docs/architecture.md](docs/architecture.md).

### Командная строка и внешний терминал (Linux)

`cd`, `cd ..`, `cd ~` и `cd "путь с пробелами"` продолжают менять каталог
активной панели внутри Marten Commander. Другие непустые команды запускаются
только по Enter во внешнем терминале. Enter в поле команды не открывает файл
под курсором. Команда получает снимок каталога активной локальной панели;
переключение панелей после Enter на неё не влияет. SFTP/SSH-консоли нет.

По умолчанию `auto` ищет `xdg-terminal-exec`, затем `gnome-terminal`, `ptyxis`,
`konsole`, `xfce4-terminal` (в таком порядке). `xdg-terminal-exec` выбирает
системный терминал по своим настройкам; без него первым кандидатом будет GNOME
Terminal. Поддержаны отдельные адаптеры аргументов всех пяти программ.

Как и настройки редактора F4, настройки терминала задаются переменными окружения
**до запуска приложения**, без отдельного экрана настроек:

| Переменная `MARTEN_COMMANDER_TERMINAL_…` | Значение |
| --- | --- |
| `MODE` | `auto` (по умолчанию) или `custom` |
| `EXECUTABLE` | В `custom`: имя в PATH или абсолютный путь к исполняемому файлу |
| `ADAPTER` | В `custom`: `xdg-terminal-exec`, `gnome-terminal`, `ptyxis`, `konsole` или `xfce4-terminal` |
| `ARGUMENTS` | Дополнительные параметры терминала, JSON-массив строк, по умолчанию `[]` |
| `SHELL` | Оболочка с поддержкой `-c`, по умолчанию `/bin/bash` |
| `SHELL_ARGUMENTS` | Параметры оболочки перед `-c`, JSON-массив строк, по умолчанию `[]` |
| `HOLD` | `true` (по умолчанию): показать код выхода и ждать Enter; `false`: завершить процесс окна сразу после команды |

Пример:

```bash
export MARTEN_COMMANDER_TERMINAL_MODE=custom
export MARTEN_COMMANDER_TERMINAL_EXECUTABLE=/usr/bin/gnome-terminal
export MARTEN_COMMANDER_TERMINAL_ADAPTER=gnome-terminal
export MARTEN_COMMANDER_TERMINAL_ARGUMENTS='["--maximize"]'
export MARTEN_COMMANDER_TERMINAL_SHELL=/bin/bash
export MARTEN_COMMANDER_TERMINAL_SHELL_ARGUMENTS='["--noprofile","--norc"]'
export MARTEN_COMMANDER_TERMINAL_HOLD=true
```

Аргументы настроек — уже разделённые строки, не shell-команда. Не добавляйте в
них флаг запуска программы (`-e`, `--execute`, `--`) или `-c`: их добавляет
адаптер. Для `custom` выбирайте адаптер, соответствующий протоколу executable.
Обёртки допустимы, если сохраняют этот протокол. Shell startup-файлы и настройки
профиля терминала могут менять окружение и поведение оболочки.

Текст команды передаётся выбранной оболочке одним аргументом, поэтому работают
кавычки, переменные, pipes и перенаправления. Сам терминал запускается через
`exec.Command` с отдельными argv, без shell-конкатенации. Каталог задаётся через
`Cmd.Dir` и параметр эмулятора, никогда не вставляется в shell-код. При `HOLD=true`
в терминале работает фиксированный `/bin/sh`-сценарий: запускает выбранную оболочку
через `"$@"`, сохраняет её код выхода и ждёт Enter с `/dev/tty`. Исходный текст
команды не дополняется; даже `exit` завершает только дочернюю оболочку. `python3`,
`bash` и `read` получают ввод непосредственно из терминала. Закрытие окна вручную
может завершить запущенную в нём команду.

Ошибки обнаружения и непосредственного запуска показываются в интерфейсе.
Запуск ожидает быстрые ошибки не более 300 мс; выполнение долгой команды не
блокирует UI. Более поздние ошибки shell видны в терминале. Для Windows и других
ОС предусмотрена граница `TerminalLauncher`, реализация пока сообщает о
неподдерживаемой платформе.

Ручная проверка Ubuntu GNOME: запустить `pwd`, `git status`, `ls -la`,
`printf '%s\n' 'a;b' 'Привет мир' | cat > 'выход файл'` из разных панелей и каталога
с пробелами; переключить панель сразу после Enter. Проверить `python3` и
`read -r answer; printf '%s\n' "$answer"`, оба режима `HOLD`, отображение stderr
и кода выхода (`exit 7`), отсутствие терминала/ошибочный custom executable,
а также неизменное поведение `cd` и F4/F5/F6/F7.

Опциональный автоматический smoke test открывает настоящие окна в графической
Linux-сессии (auto, GNOME Terminal и Ptyxis должны быть установлены):

```bash
MARTEN_TERMINAL_SMOKE=1 go test -v ./internal/localfs -run TestTerminalGraphicalSmoke
```

Обычные unit-тесты GUI-окна не открывают; launcher в них подменяется.

### F8 — только системная корзина

F8 и нижняя кнопка «Удалить» вызывают одну команду `file.trash`. При наличии
выделения используются выделенные объекты, иначе — объект под курсором. `..`,
корни томов, каталоги корзины и их служебные пути исключены. В подтверждении
«Переместить в корзину?» показаны количество, имена, исходный каталог и пояснение
о восстановлении средствами ОС. Каталог считается одним объектом и переносится
целиком с содержимым. «Отмена», Escape и закрытие диалога ничего не перемещают.

На Linux `TrashService` использует платформенный `core.TrashBackend`, реализация
`localfs.SystemTrash` вызывает **`gio trash -- <абсолютный путь>`** отдельно для
каждого объекта. Запуск идёт через `exec.Command`, без shell, `--force` и
конкатенации команд. GIO отвечает за расположение корзины на соответствующем
томе, уникальные имена и метаданные восстановления. Сервис дожидается exit status
и проверяет отсутствие исходного пути: одного успешного старта процесса
недостаточно. Симлинк переносится как ссылка; содержимое его цели не обходится.

При отсутствии GIO, неподдерживаемой корзине, ошибке прав или read-only томе
операция завершается с ошибкой. **Fallback к безвозвратному удалению отсутствует**:
адаптер F8 не вызывает `os.Remove`, `os.RemoveAll`, `rm` или `gio remove`.
Очистка корзины, восстановление внутри Marten Commander, удалённые SFTP/SSH
операции и Windows-реализация в эту версию не входят. Windows-адаптер явно
сообщает, что корзина ещё не поддерживается.

Операция использует существующий OperationManager и снимок источников. Смена
панелей, выделения и каталога после подтверждения не меняет этот снимок. Окно
«Операции» можно закрыть и открыть повторно. Прогресс показывает «В корзине: N / M»
и текущий объект; прогресс по байтам не показывается. При первой ошибке обработка
останавливается, отображается частичный результат. После завершения, ошибки или
отмены обновляются обе панели, если они всё ещё показывают исходный каталог;
навигация не откатывается, оставшиеся выделения и позиция курсора сохраняются
существующим механизмом обновления панели.

Отмена останавливает **следующие** объекты. Уже начатый вызов GIO не убивается:
сначала учитывается его фактический результат. Пока он выполняется, отображается
«Отмена после текущего объекта…», остальные операции и UI остаются доступны.
Если два объекта из пяти уже перенесены, они остаются в корзине; автоматического
восстановления нет. Если последний объект успел успешно завершиться, итог —
«Завершена», поскольку весь список действительно обработан.

Перед открытием подтверждения выполняется read-only `PrepareTrash`: фиксируются
канонический родительский путь и fingerprint (device/inode, тип, размер, mtime,
ctime). Перед каждым `gio trash` идентичность проверяется снова. Подмена файла
или родительского симлинка во время диалога приводит к отказу. Изменение файла
на месте также может потребовать повторного подтверждения. Сохраняется узкое
**TOCTOU-окно между проверкой и обращением GIO к пути**: CLI не принимает inode
или файловый дескриптор в качестве условия переноса. Это не атомарная защита от
злонамеренного конкурентного процесса. Содержимое вложенного дерева не
фиксируется рекурсивно: переносится каталог с содержимым на момент операции.

Защита путей учитывает `$XDG_DATA_HOME/Trash` (по умолчанию
`~/.local/share/Trash`), её предков и потомков, компоненты `.Trash`/`.Trash-*`,
симлинки в родительском пути, корни и содержащие точки монтирования каталоги из
`/proc/self/mountinfo`. Проверка консервативна: каталог с зарезервированным именем
`.Trash-*` блокируется и вне корня тома.

Ручная проверка Ubuntu GNOME:

1. Создайте новый тестовый каталог `~/marten-trash-test/manual-<уникальное имя>`
   и несколько тестовых файлов, включая `Привет мир.txt`, пустой файл, каталог
   с вложениями и симлинк на отдельный тестовый файл.
2. В Marten Commander выберите один объект, нажмите F8 и отмените через Escape.
   Затем проверьте множественное выделение и нижнюю кнопку «Удалить».
3. Подтвердите перенос. Проверьте «Операции», исчезновение источников, сохранение
   цели симлинка и неизменность каталогов обеих панелей. Для пакета проверьте отмену:
   уже перенесённые объекты должны остаться в корзине.
4. Откройте «Файлы» (Nautilus) → «Корзина», найдите **свой тестовый объект**, выберите
   «Восстановить» и проверьте исходный путь и содержимое. `gio trash --list` позволяет
   дополнительно проверить исходные пути; не очищайте корзину целиком.
5. Повторите на внешнем томе, если он доступен. Проверьте F4/F5/F6/F7 и нижнюю
   командную строку после закрытия диалога.

Обычные unit-тесты подменяют системную корзину и не затрагивают пользовательские
документы. Опциональный integration test создаёт только новые fixtures,
перемещает их через настоящий адаптер GIO, проверяет список корзины и восстанавливает
только эти fixtures. Восстановленные файлы оставляются для осмотра:

```bash
MARTEN_TRASH_SMOKE=1 go test -v ./internal/localfs -run TestTrashGIOSmoke
# Для внешнего тома:
MARTEN_TRASH_SMOKE=1 MARTEN_TRASH_SMOKE_ROOT=/media/ext \
  go test -v ./internal/localfs -run TestTrashGIOSmoke
```

Проверено на Ubuntu: домашняя корзина и отдельный ext4-том `/media/ext`;
в обоих случаях восстановлены шесть объектов, включая два одноимённых файла,
пустой файл, пустой каталог, вложенное дерево и симлинк.
